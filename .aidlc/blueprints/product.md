# Product

## Summary
- **Product**: Mbus Register — แอพแท็บเล็ตสำหรับลงทะเบียนรถที่จุดตรวจวัดพระธรรมกาย
- **Users**: เจ้าหน้าที่จุดตรวจ (ผู้ใช้หลักรายเดียว)
- **Type / Scope**: Brownfield / refactor — เปลี่ยนวิธีเขียน style ไม่เปลี่ยนพฤติกรรม

## Overview
แอพ Android-first ที่ใช้หน้างานจริงในลานจอดรถ เจ้าหน้าที่ถ่ายรูปทะเบียนรถ ระบบอ่านด้วย OCR เทียบกับใบ C7 ที่ลงทะเบียนไว้ล่วงหน้า บันทึกลงเครื่องก่อน แล้วค่อยส่งขึ้น server เบื้องหลัง จบด้วยการพิมพ์สลิปกระดาษให้ผู้โดยสาร ออกแบบให้ทำงานต่อได้แม้เน็ตล่ม เครื่องพิมพ์ไม่ติด หรือ OCR ใช้ไม่ได้

## Problem Statement
งานนี้แก้ปัญหาฝั่งผู้พัฒนา ไม่ใช่ฝั่งผู้ใช้: style ปัจจุบันเป็น `StyleSheet.create` กระจายใน 22 ไฟล์ รวม ~1,970 บรรทัด ไม่มี design token ไม่มีธีม และสีถูกเขียนเป็น hex ตรงในไฟล์ **54 สีไม่ซ้ำ** ทำให้ปรับหน้าตาให้สม่ำเสมอทั้งแอพได้ยาก และแก้สีหนึ่งจุดต้องไล่หาทั้งโปรเจกต์

## Target Users
- **เจ้าหน้าที่จุดตรวจ**: ยืนทำงานกลางแจ้ง ใช้แท็บเล็ตเครื่องเดียวต่อเนื่องทั้งกะ เป้าหมายคือลงทะเบียนรถให้เร็วและไม่ตกหล่น

## Key Features
- **สแกนและลงทะเบียน**: กล้อง → OCR → เทียบใบ C7 → บันทึก → พิมพ์สลิป
- **ทำงานแบบ local-first**: บันทึกลง SQLite ก่อนเสมอ แล้ว sync ขึ้น server ทีหลัง
- **พิมพ์สลิป Bluetooth ESC/POS**: render เป็น view แล้วแคปเป็นภาพส่งเข้าเครื่องพิมพ์
- **หน้าตั้งค่า**: สลับโหมด/environment, รหัสเครื่อง, export ฐานข้อมูล, ตัวนับ sync, รายการ "รถที่เหลือ"

## Domain Language

| Term | Definition | Example |
|---|---|---|
| ใบ C7 (register) | ทะเบียนรถที่ลงทะเบียนไว้ล่วงหน้ากับกิจกรรม | ตาราง `registers` |
| check-in | การลงทะเบียนรถหนึ่งคันที่จุดตรวจ | ตาราง `check_ins` |
| กิจกรรม (project) | งานบุญหนึ่งครั้ง มีช่วงเวลาเริ่ม-จบ | ตาราง `projects` |
| โหมดหนึ่ง / โหมดสอง | งานบุญ (อิง `project_id`) / ธรรมยาตรา (อิง `activity_id`) | `appMode` ใน `settings` |
| รหัสเครื่อง | รหัสประจำแท็บเล็ตที่ติดไปกับทุก check-in | `comp_id` |
