# Maestro — เทสต์ UI อัตโนมัติบน SUNMI V3

Flow ในโฟลเดอร์นี้สั่งแอปบน**เครื่องจริง**ผ่าน USB ให้กดเหมือนคน แล้วตรวจสิ่งที่ขึ้นบนจอ
ครอบคลุมส่วนที่ Jest (`npm run test:ci`) ทดสอบไม่ได้ — หน้าจอ เครื่องพิมพ์จริง และการคุยกับ server จริง

| flow | ตรวจอะไร |
|---|---|
| `01_home` | เปิดแอปแล้วถึงหน้าหลัก ไม่มีแถบเตือน "ยังไม่ได้เชื่อมเครื่องพิมพ์" (SUNMI ใช้เครื่องพิมพ์ในตัว) |
| `02_printer_test` | ตั้งค่า → ทดสอบเครื่องพิมพ์ → ต้องขึ้น "พิมพ์ผ่านเครื่องพิมพ์ในตัว (SUNMI)" — **มีสลิปออกมา 1 ใบ** |
| `03_check_update` | ตั้งค่า → ตรวจหาอัปเดต → "เป็นเวอร์ชันล่าสุดแล้ว" (หรือดาวน์โหลดได้ถ้ามี OTA ใหม่) |
| `04_resync_c7` | ตั้งค่า → ดึงใบ C7 ใหม่ทั้งหมด → มีแค่ปุ่มยืนยัน ไม่ถามรหัส → "ดึงใบ C7 เสร็จแล้ว" และตัวเลขบนการ์ด "ใบ C7" เท่ากับจำนวนที่บันทึก |
| `05_scan_no_c7` | กล้อง → OCR ไม่เจอป้าย → กรอกทะเบียนเอง (สุ่ม `ทด####`) → "ไม่พบC7" → บันทึก (โหมดธรรมยาตรา) → การ์ด "ส่งแล้ว" → หน้ารายละเอียด "ส่งขึ้นเซิร์ฟเวอร์แล้ว" |
| `06_scan_c7_print` | หยิบใบ C7 ที่ยังไม่สแกนจาก "รถที่เหลือ" → สแกน → ประเภทรถเติมเอง → บันทึกและพิมพ์ → "ส่งแล้ว" → ค้นหาบน server เจอ และไม่มีปุ่มพิมพ์ซ้ำ → รอบ sync ดึงสถานะกลับ รถหายจาก "รถที่เหลือ" → สแกนซ้ำขึ้น "ลงทะเบียนแล้ว" — **สลิป 1 ใบ** |
| `07_offline_queue` | เปิดโหมดเครื่องบิน → สแกนและบันทึกได้ → การ์ดค้าง "รอส่ง" → ปิดโหมดเครื่องบิน → "ส่งแล้ว" เองภายใน 2 นาที |
| `08_mode_one_passengers` | สลับเป็นโหมดงานบุญ (รหัสอนุมัติ) → สแกนรถมี C7 → "ต่อไป" → ตัวนับเริ่มจากจำนวนในใบ C7 → ผู้ใหญ่ +3 → บันทึกและพิมพ์ → ชิปบนการ์ดตรงจำนวน → "ส่งแล้ว" → สลับโหมดกลับ — **สลิป 1 ใบ** |

**05–08 สร้างเช็กอินจริงบน server** และ 06/08 ใช้ใบ C7 ที่ยังไม่สแกนไป 1 ใบต่อรอบ จึงเช็ก Environment ก่อน (`subflows/require_test_env.yaml`) ถ้าไม่ใช่ **Test** จะหยุดก่อนเปิดกล้อง
เมื่อ "รถที่เหลือ" ใน Test หมด 06/08 จะหยุดตั้งแต่ต้น — ต้องให้หลังบ้านเพิ่มใบ C7 ทดสอบ หรือล้างการสแกนของกิจกรรมทดสอบ

### ภาพที่กล้องถ่ายไม่สำคัญ
Maestro ป้อนภาพเข้ากล้องไม่ได้ flow จึงกดชัตเตอร์ของแอปกล้อง SUNMI (Snapcam) ถ่ายอะไรก็ได้ที่อยู่หน้าเลนส์ (มักเป็นโต๊ะ)
OCR หาป้ายไม่เจอ แล้วแอปเปิดกล่องกรอกทะเบียนเอง — ทางเดียวกับป้ายที่อ่านไม่ออกหน้างาน **อย่าวางป้ายทะเบียนไว้หน้ากล้องตอนรัน** ไม่งั้น OCR อ่านได้แล้วกล่องกรอกจะไม่เปิด

## ต้องทดสอบด้วยมือ (Maestro ทำแทนไม่ได้)

| เรื่อง | ทำไมอัตโนมัติไม่ได้ | วิธีตรวจ |
|---|---|---|
| ความแม่นของ OCR บนป้ายจริง | ป้อนภาพเข้ากล้องไม่ได้ | ถ่ายป้ายจริง 5–10 คัน ดูว่าไม่ต้องแก้ทะเบียน/จังหวัด (ตัวเลขดิบดูได้จาก instrumented test ดู CLAUDE.md § On-device OCR) |
| กระดาษหมด / ฝาเปิด | ต้องถอดกระดาษจริง | ถอดกระดาษ → สแกนรถมี C7 → ต้องขึ้น "เครื่องพิมพ์ไม่พร้อม … ยังไม่ได้บันทึกข้อมูล" และไม่มีการ์ดใหม่ → ใส่กระดาษ → "พิมพ์อีกครั้ง" → สลิปออกและบันทึก |
| กระดาษหมดกลางสลิป | จังหวะทำซ้ำไม่ได้ | ใส่กระดาษเหลือน้อย → ต้องขึ้น "พิมพ์ไม่สำเร็จ" แบบมีปุ่มลองพิมพ์ซ้ำ และไม่เกิดการ์ดซ้ำ |
| หน้าตาสลิปบนกระดาษ | Maestro เห็นแค่จอ | ดูสลิปจาก 02/06/08: ไม่ตกขอบ ภาษาไทยไม่แตก โหมดงานบุญมี 2 ส่วน |
| พิกัด Lat/Long | อ่านจาก server ไม่ได้จาก flow | ครั้งแรกกด "อนุญาต" ตำแหน่ง → สแกน → ดูในระบบหลังบ้านว่าไม่ใช่ 0 หรือว่าง |
| ล็อกอิน / ออกจากระบบ | flow ไม่ใส่รหัสผ่าน | ออกจากระบบ → ล็อกอิน → ต้องเข้าหน้าหลักเองโดยไม่ผ่านหน้าเลือกเครื่องพิมพ์ |
| token หมดอายุ (401) | ต้องให้ server ยกเลิก token | ยกเลิก token ที่หลังบ้าน → ภายใน 10 วิ แอปต้องเด้งไปหน้าล็อกอิน และรายการรอส่งไม่หาย |
| จอดับแล้ว sync หยุด | อาการตั้งใจ (ดู CLAUDE.md) | ปิดจอ 5 นาทีระหว่างมีรายการรอส่ง → เปิดจอ → ต้องส่งต่อเอง |
| สลับ Environment / OTA ใหม่จริง | เปลี่ยนสภาพเครื่องถาวร | ทำตอนมีเหตุจริง |
| สองเครื่องสแกนคันเดียวกันพร้อมกัน | ต้องใช้ 2 เครื่อง | ภายใน 10 วิ ทั้งสองเครื่องบันทึกได้ (ข้อจำกัดที่รู้อยู่ ดู CLAUDE.md) |


## ก่อนรัน

1. **ติดตั้ง Maestro** (ใช้ Homebrew ไม่ได้บน Mac เครื่องนี้ เพราะ Xcode 16.2 เก่าเกิน Homebrew ปฏิเสธทุกอย่าง)
   ```bash
   mkdir -p ~/.maestro && cd ~/.maestro
   curl -L -o maestro.zip https://github.com/mobile-dev-inc/Maestro/releases/download/cli-2.12.1/maestro.zip
   unzip -q maestro.zip && rm maestro.zip
   export PATH="$HOME/.maestro/maestro/bin:$PATH"
   ```
   ต้องมี Java 17 (มีอยู่แล้ว: zulu-17) และพื้นที่ว่างราว 400 MB
2. **เสียบ SUNMI** เปิด USB debugging แล้ว `adb devices` ต้องเห็นเครื่อง
3. **ติดตั้งแอปตัวทดสอบ** (`com.donnytang.myapp.dev`) — ไม่ทับแอปตัวจริงและข้อมูลในเครื่อง
   ```bash
   cd android && rm -rf app/build/generated/assets/createReleaseUpdatesResources app/build/intermediates/assets/release/app.manifest
   ./gradlew :app:assembleRelease -Pmbus.appIdSuffix=.dev
   adb install -r app/build/outputs/apk/release/app-release.apk
   ```
4. **ล็อกอินในแอปตัวทดสอบด้วยมือหนึ่งครั้ง** และตั้ง Environment เป็น **Test** — flow ไม่ล็อกอินให้ และจะไม่ล้าง session
5. ใส่กระดาษในเครื่องพิมพ์ และต่อ wifi ที่ออกเน็ตได้

## รัน

```bash
export PATH="$HOME/.maestro/maestro/bin:$PATH"
maestro test .maestro                       # ทุก flow ตามลำดับใน config.yaml (~15 นาที สลิป 3 ใบ)
maestro test .maestro/02_printer_test.yaml  # flow เดียว
maestro test .maestro --test-output-dir /tmp/maestro-out   # เก็บภาพหน้าจอผลลัพธ์ไว้ดู
```

รันกับแอปตัวจริงแทน: `maestro test -e APP_ID=com.donnytang.myapp .maestro` — **ระวัง** flow 02 พิมพ์สลิปจริง และ flow 04 ดึงใบ C7 ของ environment ที่ตั้งไว้ในเครื่อง

## ข้อควรรู้

- **แท็บด้านล่างไม่มีข้อความ** flow จึงแตะตามตำแหน่ง (`subflows/open_settings.yaml`, 83% / 91% ของจอ) ถ้าเปลี่ยนจำนวนหรือลำดับแท็บ ต้องแก้ตรงนั้น
- กล่อง Alert ของ Android ใช้ปุ่ม `OK` ที่ระบบใส่ให้เมื่อโค้ดไม่ได้กำหนดปุ่มเอง
- **ปลุกจอก่อนรัน** — จอดับแล้ว Maestro มองไม่เห็นอะไร flow แรกจะล้มที่ "ค้นหาทะเบียน" (`adb shell input keyevent KEYCODE_WAKEUP`)
- **ห้ามใช้ `hideKeyboard` ตอนมีกล่อง (Modal) เปิด** — บน Android มันกด Back ซึ่งปิดกล่องทิ้ง
- ตัวเลือกใน dropdown ค้นหาได้ (`Type something...`) — พิมพ์ชื่อแล้วแตะ `index: 1` เพราะตัวแรกที่ตรงคือช่องค้นหาเอง
- ตัวนับผู้โดยสารโหมดงานบุญเริ่มจากจำนวนในใบ C7 ไม่ใช่ 0
- flow 03–08 ต้องคุยกับ server จริง — ถ้า `mbus-test.dhammakaya.network` ล่มหรือเน็ตใช้ไม่ได้ จะขึ้น "ดึงใบ C7 ไม่สำเร็จ / Network Error" และ flow ล้ม ซึ่งเป็นผลที่ถูกต้อง (แอปแจ้ง error ได้ชัด) แต่ไม่ใช่การยืนยันว่าดึงสำเร็จ
- **build บน Mac ต้องมี header `expo-channel-name`** ใน AndroidManifest (`UPDATES_CONFIGURATION_REQUEST_HEADERS_KEY`) ไม่งั้นปุ่มตรวจหาอัปเดตขึ้น "ตรวจหาอัปเดตไม่สำเร็จ" เพราะ server ของ Expo ตอบว่าขาด channel — EAS ใส่ให้เองตอน build แต่ build บน Mac ไม่ได้ใส่ จนกว่าจะเพิ่มไว้ในไฟล์
